# 陸期 × 台股 多空儀表板

以大陸三大商品交易所（上期所含 INE、大商所、鄭商所）主力合約漲跌，透過「商品 → 三竹類股」關聯權重，每日找出台股 **多頭助攻前 3 類股** 與 **空頭壓力前 3 類股**，並列出每個類股的 **前 5 強／前 5 弱** 個股。

例：大商所乙二醇（EG）漲停 → 塑膠類股（南亞、台化）與化學工業（東聯）分數大幅上升，成為多頭助攻燃料。

## 部署（約 3 分鐘）

1. 在 GitHub 建立新 repo（例：`MaxTrader0207/cn-tw-commodity-dashboard`），把本資料夾內容推上 `main`。
2. Settings → Pages → Source 選 **GitHub Actions**（`deploy.yml` 第一次執行時也會自動切換）。
3. Actions 頁籤 → **Daily update** → Run workflow，跑第一次資料。
4. 開啟 `https://<帳號>.github.io/<repo>/`。

之後自動排程（台北時間）：
- 週一～五 **17:10**：日盤收盤版（陸期日盤收盤 + 台股當日收盤）
- 週二～六 **06:17／06:47／07:13／07:41／08:07**：盤前版（陸期夜盤＋前一晚已收盤的美國期貨），多次嘗試、第一個準時完成的生效；
  GitHub 排程延遲到 09:00 之後會自動略過
- 每週六 **10:20**：重新校準實測權重與回測（`calibrate.yml`）

## 檔案

| 檔案 | 用途 |
|---|---|
| `pipeline/mapping.py` | 商品 ↔ 類股關聯表（權重、邏輯說明、漲跌停幅度）— 想調整關聯就改這裡 |
| `pipeline/build.py` | 抓資料、計分、輸出 `docs/data/latest.json` 與歷史檔 |
| `docs/index.html` | 儀表板頁面（GitHub Pages） |
| `tests/make_fixtures.py` | 產生離線假資料：`python tests/make_fixtures.py /tmp/fx && python pipeline/build.py --fixtures /tmp/fx` |

## 資料來源

- 陸期：新浪財經期貨行情 `hq.sinajs.cn`（`nf_XX0` 連續主力），漲跌幅以昨結算為基準
- 台股：證交所 OpenAPI `STOCK_DAY_ALL`、`t187ap03_L`；櫃買中心 OpenAPI 上櫃收盤與公司基本資料
- 類股：以證交所／櫃買產業別代碼歸類，對應三竹傳產類股名稱（塑膠、鋼鐵、航運、電器電纜…）

## 計分

- 商品訊號 = 今日漲跌 ÷ 近 20 個交易日波動度（z 分數；穩健估計＝中位數絕對離差 × 1.4826），2σ 為滿格 ±1；觸及漲跌停再 ×1.5。
  抓不到日K時退回「漲跌幅 ÷ 漲跌停幅度」；設定環境變數 `NORM=limit` 可強制使用舊算法。價差同樣以 20 日波動度標準化
- 類股分數 = Σ(權重 × 商品訊號) ÷ √Σ|權重| × 100
- 共振 = 陸期訊號方向與台股類股當日平均漲跌同向
- 個股排行只計成交量 ≥ 100 張（`MIN_LOTS`）

漲跌停幅度 `limit` 為一般值，交易所會依行情調整，可在 `mapping.py` 更新。

## 立即更新按鈕

儀表板右上角「⟳ 立即更新」：

- **未設定 Worker**（預設）：開啟 GitHub Actions 頁面，按 Run workflow 後，儀表板會自動偵測並載入新資料。
- **設定 Worker 後**：按一下直接觸發更新，約 1–2 分鐘自動載入，不用離開頁面。

設定 Worker：
1. GitHub → Settings → Developer settings → Fine-grained tokens → 新增 token，Repository access 只選本 repo，權限 **Actions: Read and write**。
2. Cloudflare → Workers → 新建 Worker，貼上 `worker/trigger-worker.js`，部署。
3. Worker → Settings → Variables and Secrets → 新增 Secret `GH_TOKEN` = 上一步的 token，
   再新增 Secret `ADMIN_KEY` = 自訂的管理密碼（至少 20 字元）。
4. 把 Worker 網址填進 `docs/config.js` 的 `triggerUrl`。

## 資料來源狀態

每次執行都會寫出 `docs/data/status.json`（成功或失敗都會寫），儀表板上方「資料來源狀態」逐一列出：新浪陸期、證交所上市產業別、ISIN 上櫃產業別、證交所上市收盤、櫃買上櫃收盤，各自的狀態（正常／注意／失敗）、筆數、資料日與抓取時間。

## 訊號驗證

- **實測權重**（`pipeline/calibrate.py`）：近 2 年陸期主力日報酬 × 證交所類股指數超額報酬（類股 − 加權指數）。
  每組「商品 → 類股」算同日相關 ρ0 與隔日相關 ρ1；|t| ≥ 2 且前後兩段方向一致才採用，不顯著的權重歸 0，
  對照表外 |t| ≥ 4 的組合列為「數據新增」。結果寫在 `docs/data/calibration.json`，每日計分自動改用實測權重
  （設定環境變數 `WEIGHTS=manual` 可改回手動）。
- **樣本外回測**：前 60% 期間校準、後 40% 期間測試，比較手動 vs 實測權重選出的多空前 3 類股，當日與隔日超額報酬。
- **實盤命中率**（`pipeline/track.py`）：每次訊號記入 `docs/data/track/signals.json`，以下一個台股交易日的類股指數超額報酬開獎，
  彙整在 `docs/data/track.json`。夜盤版 09:00 後、日盤版 15:00 前產生的訊號視為延遲，不計入。

## 價差與受惠個股

- **價差（加工利潤）**（`mapping.py` 的 `SPREADS`）：螺紋鋼／熱卷利潤、PTA／短纖／瓶片加工費、PX／PP／PE 對原油、
  燃料油裂解、玻璃利潤、大豆壓榨、養殖利潤共 13 組。每日變化 = Δ價差 ÷ 產品前一日結算價；訊號以歷史 2σ 為滿格，
  與單一商品一樣經過實測校準才計分。
- **受惠／受壓個股**（`mapping.py` 的 `BENEFICIARIES`）：47 檔，標註「產品」或「成本」角色。校準時以 Yahoo 2 年日線
  （還原權息）計算個股 β 調整報酬與陸期的相關，並分前 60%／後 40% 做樣本外檢驗。
- 輸入資料保存在 `pipeline/cache/calib_inputs.json.gz`，可在本機重現校準結果。

## 交易日曆與主力換月

- **台股休市日**：每次執行抓證交所休市日 OpenAPI（快取於 `pipeline/cache/tw_holidays.json`），「應有交易日」排除週末與公告休市日；
  名稱含「開始交易」「最後交易」的是照常交易的日子，不算休市。
- **大陸休市偵測**：陸期報價與上一次快照完全相同、且超過 18 小時未更新 → 視為休市，頁面顯示提示，這次訊號不記入命中率帳本。
- **主力換月（歷史）**：校準時抓各個別合約日K（如 `EG2601`），比對新浪連續主力每天實際的合約；換約日改用新合約自己的前一日結算價，
  去除「新合約價 ÷ 舊合約結算」造成的假漲跌。比對結果快取於 `pipeline/cache/rollmap.json`，每週只補新日期。
- **主力換月（即時）**：今天報價的昨結算 ≠ 上次快照記下的結算價 → 標示「換月」，漲跌以新合約的昨結算計算。

## 廣期所、國際商品與籌碼面

- **廣州期貨交易所**：碳酸鋰（LC）、工業矽（SI）、多晶矽（PS），對應化學工業（電池材料）、光電（太陽能）、綠能環保等，
  受惠股含康普、美琪瑪、立凱-KY、茂迪、聯合再生、元晶、中美晶；成本受壓含順達、新普。與其他陸期一樣做換月修正與實測校準。
- **國際商品對照**（`mapping.py` 的 `INTL`）：Yahoo 的 Brent／WTI 原油、柴油、汽油、COMEX 銅／鋁／白銀、CBOT 黃豆／豆粕／豆油／玉米、
  ICE 棉花／原糖。頁面標示與對應陸期「同向／背離」；校準時把美國 D 日漲跌對齊到 D 之後第一個台股交易日，檢驗隔夜美盤對台股的預測力，
  並計算陸期是否跟隨前一晚的國際價格。只做交叉確認，不計入類股分數。
- **籌碼面**：前 5 強／弱與受惠股顯示三大法人買賣超（張，證交所 T86＋櫃買）、量比（今日量 ÷ 前 5 日均量）、融資融券增減（滑鼠移上去看明細）。
  成交量歷史存於 `pipeline/cache/vol_hist.json`：上市股缺少的日子用證交所 MI_INDEX 回補，上櫃股逐日累積（約 3 個交易日後開始有量比）。

## 盤前版計分

- 盤前分數 = 陸期夜盤（目前權重）＋ 國際隔夜：前一晚已收盤的美國日線（紐約 17:00 收盤）漲跌 ÷ 前 20 日波動度，
  乘以實測的「美盤 D 日 → D 之後第一個台股交易日」權重（`calibration.json` 的 `intl.live_links`）。日盤版不計國際。
- 回測（`calibrate.py`）：國際、陸期都對齊到「資訊之後第一個台股交易日」，前 60% 期間定權重、後 40% 測試，
  比較「僅國際隔夜」「僅陸期前一日」「國際＋陸期」。陸期夜盤無法從日K單獨取出，以前一日代替。

## 多日動能、漲跌停自動更新、覆蓋範圍、分數熱力圖

- **多日動能**：商品看板每格顯示 5 日／20 日累計漲跌 ÷ (σ × √天數)。校準時用樣本外回測比較 1 日、5 日、20 日與
  「1 日 ＋ 0.5 × 5 日」組合；組合版隔日 t 值比 1 日版高 0.3 以上、且同日 t 值不低於 1 日版 −0.3，才自動加進即時分數
  （`calibration.json` 的 `momentum.adopt`）。
- **漲跌停幅度自動更新**：每次執行抓上期所、上海國際能源中心（`ContractDailyTradeArgument{日期}.dat`）與鄭商所
  （`FutureDataClearParams.txt`）公告的每日漲跌停幅度，同一商品取各合約的眾數，快取於 `pipeline/cache/limits.json`。
  大商所、廣期所官網有反爬蟲機制，沿用 `mapping.py` 的預設值。與預設值不同的商品在看板標「停板 X%」。
- **類股覆蓋範圍**：訊號驗證區列出每個類股有幾個商品、哪些實測有效。陸期以原物料為主，電子類股覆蓋有限；
  新增上期所黃金（AU）、錫（SN）與 COMEX 黃金補一點電子相關（貴金屬回收、焊料）。
- **產業別來源健康度**：`pipeline/cache/industry_meta.json` 記錄上市／上櫃產業別來源上次成功的日子，
  失敗且快取超過 7 天時，資料來源狀態標紅並在頁面上方警示。
- **分數熱力圖**：`docs/data/score_history.json`。校準時以全期實測權重回填最近 120 個台股交易日（樣本內），
  之後每天日盤版把實際分數記為「即時」，並用類股指數補上當天 β 調整超額報酬；可切換分數／實際報酬／方向是否一致。

## 資料分支、失敗通知、CI

- **資料分支**：每日更新與校準產生的資料（`docs/data`、`pipeline/cache`、`pipeline/industry_cache.json`）存在 `data` 分支，
  `main` 只放程式碼，不再每天被自動 commit 洗版。流程開始時 `python pipeline/datastore.py restore` 取回資料，
  結束時 `save` 推回 `data` 分支；校準中途的存檔點也推到 `data` 分支。
  網站由 `deploy.yml` 把 `main` 的 `docs/` 與 `data` 分支的 `docs/data` 組合後部署到 GitHub Pages
  （改程式 push main、每日更新、每週校準後都會自動部署）。本機要看真實資料：`python pipeline/datastore.py restore`。
- **失敗通知**（`notify.yml` + `.github/scripts/alert.py`）：每日更新／校準／部署／CI 失敗時自動開 GitHub Issue
  （標籤 `pipeline-failure`，附失敗步驟與錯誤訊息），GitHub 會寄 Email 與手機 App 推播；同一流程再失敗只加留言，下次成功自動關閉。
  每日更新雖成功、但核心來源（新浪陸期、證交所／櫃買收盤、產業別）抓取失敗時，另開「資料來源異常」Issue。
- **CI**（`ci.yml`）：每次 push／PR 執行 workflow 語法檢查（actionlint）、單元測試（`tests/test_pipeline.py`：解析器、
  標準化、無偷看、對照表完整性、離線完整 build），並用無頭瀏覽器開頁面（`tests/page_check.py`）檢查 JS 錯誤與
  桌機 1280／手機 390 是否橫向破版——分別用 `data` 分支的真實資料與離線假資料各跑一次。

## 商品詳細面板

點商品看板的任一格（或類股卡片上的商品標籤）打開詳細面板：最新價、今日 z、5／20 日動能、漲跌停（公告或預設）、持倉量；
近 120 個交易日收盤走勢與每日 z 分數（金框 = 觸及漲跌停，滑鼠／手指移動看每日數字）；最近 10 天；對應類股的手動／採用權重、
同日與隔日實測相關、判定與今日對分數的貢獻；受惠／受壓個股今日表現與實測；國際對照與陸期跟隨程度；最近換月紀錄。
網址加 `#代碼`（例如 `#EG`）可直接打開該商品。日K摘要由每日更新寫入 `docs/data/klines.json`。

## 停擺監控

`watchdog.yml` + `.github/scripts/watchdog.py`：最後一次成功更新超過 30 小時，而且之後有台股交易日的排程（06:17 盤前版、17:10 日盤版，各給 2 小時緩衝）
沒有成功 → 開 GitHub Issue「儀表板已 N 小時沒有更新」，恢復後自動關閉。週末與證交所休市日不算。
觸發互為備援：GitHub 每小時排程、Cloudflare Worker 每 4 小時（`41 */4 * * *`）。儀表板頁面也用同一規則，資料過時時在上方顯示警示。

## 管理者模式與分享

- 網頁分享給別人時，訪客**看不到**「立即更新」按鈕（顯示「資料每天自動更新」）；資料由排程自動更新，不需要手動觸發。
- 擁有者在頁尾「管理者登入」輸入管理密碼（Cloudflare Worker 的 Secret `ADMIN_KEY`，至少 20 字元），
  這台裝置才會出現更新按鈕；密碼只存在該裝置瀏覽器，可隨時登出。
- Worker 對 `/trigger` 一律檢查管理密碼（固定時間比對），沒設定或太短就拒絕所有手動觸發；定時觸發不受影響。
- 頁首有免責聲明：量化研究參考、不構成投資建議、不保證資料正確與即時。

## 手機版

`docs/m/`：專為手機設計的 App 式版面，與電腦版共用 `docs/data/`。
- 底部 5 個分頁：多空（前 3 類股卡片，可展開受惠股與前 5 強弱）、看板（依交易所篩選、依漲跌／z／5 日動能排序）、
  驗證（命中率、回測、可左右滑動的分數熱力圖）、代碼（搜尋）、更多（明暗模式、管理者登入與更新、資料來源狀態）。
- 只在打開分頁時才載入與繪製；商品詳細頁全螢幕顯示，手機返回鍵可關閉；按鈕與列至少 44px，支援 iPhone 瀏海與底部橫條。
- 手機（觸控＋寬度 ≤ 700px）打開電腦版網址會自動轉到手機版；在手機版選「切換到電腦版」或網址加 `?desktop` 會記住偏好；
  電腦版右上角「手機版」可切回。
